# SSH in Linux - Complete Notes

## What is SSH?

SSH (Secure Shell) is a network protocol that enables secure remote access to Linux systems through encrypted connections. It allows you to manage servers remotely, transfer files, and execute commands as if you were physically in front of the server. SSH is the standard remote management solution for Linux servers.

---

## SSH Components

SSH has two main components:

- **SSH Client**: What you use to connect to a remote Linux server
- **SSH Server**: What runs on the target server to listen for and accept incoming connections

## Installation and Setup

## Installing SSH on Different Systems

**Ubuntu/Debian:**

`bashsudo apt install openssh-client openssh-server`

**CentOS/Fedora/RHEL:**

`bashsudo dnf install openssh-clients openssh-server`

`bashsudo systemctl start sshd

## Connecting to a Remote Server

## Basic Connection Syntax

`bashssh username@hostname_or_ip`

**Example:**

`bashssh jay@192.168.1.174`

Source:youtube

## Simplified Connection (Same Username)

If your local username matches the remote server username, you can omit the username:

`bashssh hostname_or_ip`

SSH assumes the username is the same on both systems unless specified otherwise

## First-Time Connection

When connecting to a server for the first time, you'll see a fingerprint verification prompt:

`textThe authenticity of host 'xxx.xxx.xxx.xxx' can't be established.
Are you sure you want to continue connecting (yes/no)?`

Type `yes` and press Enter. This prompt won't appear again unless there's a security concern.

---

## Connecting with Custom Port

By default, SSH uses **port 22**. If the server listens on a different port, use the `-p` option:

`bashssh -p 2222 username@hostname`

**Example:**

`bashssh -p 2222 jay@192.168.1.169`

Source:youtube

## Why Change the Default Port?

Some administrators change the SSH port from 22 to reduce automated attacks from threat actors. While it adds minimal security, it can confuse attackers who scan for servers on the default port.

`bashsudo apt update`

`bashsudo apt dist-upgrade`

`bashexit`

## SSH Key Authentication

SSH keys provide passwordless authentication that's more secure than passwords.

## Generate SSH Key Pair

`bashssh-keygen -t rsa -b 4096 -C "your_email@example.com"`

This creates two files:[digitalocean](https://www.digitalocean.com/community/tutorials/how-to-configure-ssh-key-based-authentication-on-a-linux-server)

- **Private key**: `~/.ssh/id_rsa` (keep this secret)
- **Public key**: `~/.ssh/id_rsa.pub` (share with servers)

## Copy Public Key to Remote Server

`bashcat ~/.ssh/id_rsa.pub | ssh username@remote_host "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"`

Alternatively, use:

`bashssh-copy-id username@remote_host`

## Common SSH Options

| Option | Purpose | Example |
| --- | --- | --- |
| `-p` | Specify custom port | `ssh -p 2222 user@host` |
| `-v` | Verbose/debugging output | `ssh -v user@host` |
| `-C` | Enable compression | `ssh -C user@host` |
| `-X` | Forward GUI applications | `ssh -X user@host` |
| `-i` | Specify identity/key file | `ssh -i ~/.ssh/custom_key user@host` |
| `-J` | Connect via jump host | `ssh -J jumphost user@host` |

## SSH Configuration File

## Client Configuration

**Location:** `~/.ssh/config`

**Set proper permissions:**

`bashchmod 600 ~/.ssh/config`

**Example configuration:**

`textHost myserver
    HostName server.example.com
    User jay
    Port 2222
    IdentityFile ~/.ssh/myserver_key`

Now you can connect simply with: `ssh myserver`

## Server Configuration

**Location:** `/etc/ssh/sshd_config` (requires root privileges)

After editing, restart SSH service:

`bashsudo systemctl restart sshd`

## Troubleshooting

## Connection Refused Error

If you see "Connection refused"

- Check if SSH server is running on the target
- Verify you're using the correct port (default is 22)
- Ensure firewall allows SSH connections
- Try connecting with `p` option if custom port is used
