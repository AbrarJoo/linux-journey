# Complete Notes: Systemd Explained - Linux Service Management

## Overview

Systemd is the dominant init system across most major Linux distributions, serving as the first process (PID 1) that manages all other processes on your system. Understanding systemd is essential for managing services, especially for cybersecurity and system administration roles.youtube

## What is an Init System?

## Core Concepts

- **Init system**: The most important process on Linux, always starting first with Process ID 1 (PID 1)youtube
- **Purpose**: Manages all other processes - starting, stopping, restarting, and monitoring servicesyoutube
- **Systemd debut**: Introduced in 2010 with modern features for process managementyoutube

## Key Features

- Schedule tasks to run when specific criteria are metyoutube
- Ensure processes are always runningyoutube
- Configure logging and DNS resolutionyoutube
- Enable dependency management between servicesyoutube

## Units vs Services

## Understanding the Terminology

- **Unit**: Anything that systemd can manage (services, timers, mounts, sockets, targets)youtube
- **Service**: A specific type of unit - the most common type you'll work withyoutube
- **Service files**: Text files with `.service` extension containing instructions for systemdyoutube

## Essential Systemctl Commands

## The Six Most Important Commands

**1. Check Status**

`systemctl status <service-name>`

- Shows if service is active/inactive, enabled/disabledyoutube
- Displays recent log entries if you have permissionsyoutube

**2. Start a Service**

`sudo systemctl start <service-name>`

- Immediately starts the specified serviceyoutube

**3. Stop a Service**

`sudo systemctl stop <service-name>`

- Immediately stops the running serviceyoutube

**4. Restart a Service**

`sudo systemctl restart <service-name>`

- Stops and then starts the service (useful after configuration changes)youtube

**5. Enable a Service**

`sudo systemctl enable <service-name>`

- Configures service to start automatically at bootyoutube
- Creates a symlink in the appropriate directoryyoutube

**6. Disable a Service**

`sudo systemctl disable <service-name>`

- Prevents service from starting automatically at bootyoutube

## Additional Useful Command

- Reloads configuration files without fully restartingyoutube
- Preferred for web servers to avoid disconnecting usersyoutube
- Not all services support this featureyoutube

## Service File Directories

## Three Key Directories (Priority Order)

**1. `/etc/systemd/system/` - HIGHEST PRIORITY**

- Where you should place custom service filesyoutube
- Overrides configurations in lower priority directoriesyoutube
- Changes here are preserved during package updatesyoutube

**2. `/run/systemd/system/` - MEDIUM PRIORITY**

- Contains runtime systemd unitsyoutube
- Least commonly accessed directoryyoutube

**3. `/lib/systemd/system/` - LOWEST PRIORITY**

- Where package managers install default service filesyoutube
- Files here may be overwritten during package updatesyoutube
- Never edit files directly in this directoryyoutube

## How Priority Works

- Systemd loads unit files from all directories into memory at startupyoutube
- Configurations in higher priority directories override lower onesyoutube
- This allows safe customization without modifying distribution-provided filesyoutube

## Service File Structure

## Three Main Sections

**[Unit] Section**

- Contains general information about the unityoutube
- `Description=`: Human-readable descriptionyoutube
- `After=`: Specifies units that must start before this oneyoutube
- `Before=`: Specifies units that must start after this oneyoutube
- `Wants=`: Lists prerequisite units (soft dependency)youtube
- `Documentation=`: Points to manual pages or URLsyoutube

**[Service] Section**

- Configuration specific to service unitsyoutube
- `Type=`: Defines service startup behavior (simple, notify, forking, etc.)youtube
    - `simple`: Service considered started immediately (default)youtube
    - `notify`: Service must signal readiness to systemdyoutube
    - `forking`: Parent process spawns children then exitsyoutube
- `ExecStart=`: Command to run when service startsyoutube
- `ExecStop=`: Command to run when service stops (optional)youtube
- `ExecReload=`: Command to reload configuration without full restartyoutube

**[Install] Section**

- Configures behavior when unit is enabled/disabledyoutube
- `WantedBy=`: Defines dependency relationships and run levelsyoutube
- `multi-user.target`: Indicates system must support multiple concurrent usersyoutube

## Editing Service Files

## Method 1: Override Files (Recommended)

`sudo systemctl edit <service-name>`

- Creates override file at `/etc/systemd/system/<service-name>.service.d/override.conf`youtube
- Only include sections/settings you want to changeyoutube
- Original service file remains untouchedyoutube
- Add changes between the comment lines (not below the "discarded" warning)youtube

**Example Override:**

`text[Unit]
Description=Apache is Awesome`

## Method 2: Full Copy

`sudo systemctl edit --full <service-name>`

- Creates complete copy of service file in `/etc/systemd/system/`youtube
- Allows editing entire fileyoutube
- Protected from package manager updatesyoutube
- Use when extensive modifications neededyoutube

## Critical: Reload Daemon After Changes

`sudo systemctl daemon-reload`

- **MUST run this after any service file modifications**youtube
- Forces systemd to reload all unit files and recognize changesyoutube
- Changes won't take effect without this commandyoutube

## Practical Example: Apache Web Server

## Installation

**Debian/Ubuntu:**

`sudo apt install apache2`

**Fedora/CentOS/RHEL:**

`sudo dnf install httpd`

## Common Tasks

1. Check if Apache is running: `systemctl status httpd` or `systemctl status apache2`youtube
2. Start Apache: `sudo systemctl start httpd`youtube
3. Enable auto-start at boot: `sudo systemctl enable httpd`youtube
4. Test: Navigate to `http://localhost` in browseryoutube

## Distribution Differences

- Debian/Ubuntu: Service named `apache2`youtube
- RHEL-based: Service named `httpd`youtube
- Debian typically auto-enables services; RHEL does notyoutube

## Creating Custom Service Files

## Best Practices

1. Save custom service files in `/etc/systemd/system/`youtube
2. Check if the application developer provides a template service fileyoutube
3. Use existing service files as reference examplesyoutube
4. Ensure proper syntax: sections are case-sensitive with capitalized first lettersyoutube
5. Always run `systemctl daemon-reload` after creating/modifying filesyoutube

## Example Use Case

- Installing software manually (not via package manager) may require creating your own service fileyoutube
- Example given: SyncThing application with developer-provided service file templateyoutube
