### 📌 **Purpose of Linux Log Files**

- Store information about system and application events.
- Useful for tracking errors, security alerts, user activities.
- Important for both attackers (to hide traces) and defenders (to detect breaches).

---

### 📌 **rsyslog Overview**

- Linux uses syslogd-based daemons for logging.
- Common variants: **rsyslog**, **syslog-ng**.
- Kali Linux (Debian-based) uses **rsyslog** by default.

---

### 🔍 Key Files Related to rsyslog

Located using: `locate rsyslog`

- `/etc/rsyslog.conf` → **Main configuration file**
- `/etc/rsyslog.d/` → Additional configs
- `/etc/logrotate.d/rsyslog` → Rotation rules for logs

---

### 📁 **rsyslog Configuration File**

Path: `/etc/rsyslog.conf`

- Contains modules, global directives, and most importantly → **Logging Rules**
- Open with:
    
    ```
    leafpad /etc/rsyslog.conf
    
    ```
    

---

### 🔥 Logging Rules Structure

Format:

```
facility.priority  action

```

| Component | Meaning |
| --- | --- |
| facility | Which program/service logs (ex: auth, mail, kernel) |
| priority | Severity level (debug → emerg) |
| action | Where logs are stored, usually in `/var/log/` |

### Facility examples:

- `auth` / `authpriv` → authentication logs
- `cron` → task scheduler
- `mail` → mail system
- `daemon` → system services
- `kern` → kernel logs
- `user` → user-level logs
- → all facilities

### Priority levels (low → high):

debug → info → notice → warning(warn) → error(err) → crit → alert → emerg(panic)

⭐ Higher priority includes all levels above it.

### Examples:

```
mail.*          /var/log/mail       → all mail logs
kern.crit       /var/log/kernel     → critical kernel logs only
*.emerg         :omusmsg:*          → broadcast emergency to users

```

### 🔄 Log Rotation with **logrotate**

- Prevents logs from filling disk.
- Automatic rotation controlled by:
    
    ```
    /etc/logrotate.conf
    
    ```
    

### Key Settings:

- `weekly` → rotation interval
- `rotate 4` → number of backups to keep
- `create` → create new log after rotation
- `#compress` (optional) → compress old logs to save space

Example rotated files:

```
auth.log → auth.log.1 → auth.log.2 → auth.log.3 → auth.log.4

```

### 🔐 Stealth Techniques (Hacker Perspective)

### 1. Removing Log Evidence

- Editing logs manually = risky + suspicious
- Better method → **shred** to overwrite and destroy permanently

Example:

```
shred -f -n 10 /var/log/auth.log.*

```

Options:

| Option | Purpose |
| --- | --- |
| `-f` | force overwrite even if permissions restrict |
| `-n 10` | overwrite 10 times for deep destruction |

After shredding → logs become unrecoverable gibberish.

---

### 2. Disabling Logging Entirely

Stop rsyslog service:

```
service rsyslog stop

```

→ System stops writing logs until restarted.

⚠ Requires **root privileges**.

---

### 📝 Summary

- rsyslog handles logging in Linux.
- Rules define what gets logged and where.
- logrotate manages log size and retention.
- Attackers may shred logs or disable rsyslog to avoid detection.
- Defenders analyze logs and configure rotation for security monitoring.
